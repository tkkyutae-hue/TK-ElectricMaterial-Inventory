Part 2 — Replace native date inputs with Date Range popover

Current issue:
Two native date inputs create inconsistent browser UI and an awkward calendar popup.

Replace:
<input type="date" ... startDate />
<input type="date" ... endDate />

With:
A single Date Range trigger button.

Example trigger text:
- "Apr 21 – May 21"
- "Today"
- "Last 7 days"
- "Last 30 days"
- "This Month"
- "Custom Range"

Recommended layout in toolbar:
[Today] [7 Days] [30 Days] [This Month]  [Apr 21 – May 21 ▼]  [All Types] [All Projects]

Behavior:
- Existing quick date chips must still work.
- Clicking Today / 7 Days / 30 Days / This Month should update startDate/endDate and datePreset.
- The Date Range button should open a Popover.
- Selecting custom dates in the popover should set datePreset = "custom".
- Existing filtering behavior must remain unchanged.

Popover UI:
- Title: Date range
- Show existing quick presets inside the popover if useful, or keep presets outside and only show calendar in popover.
- Use Calendar component.
- Prefer range selection if Calendar supports mode="range".
- If range mode is too risky, use two small date selectors inside the popover but styled consistently.
- Show Apply and Cancel if the range is staged.
- Or apply immediately if simpler and consistent with current behavior.

Important date behavior:
- startDate and endDate should remain stored in YYYY-MM-DD string format for existing query/filter logic.
- Convert between Date objects and YYYY-MM-DD safely.
- Avoid timezone off-by-one errors.
- Use date-fns format where already used.
- Respect existing language/locale if simple:

  - KO
  - ES
