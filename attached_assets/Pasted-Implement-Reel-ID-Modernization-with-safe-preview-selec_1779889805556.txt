Part 1 — Update new Reel ID generator

Update generateReelId() in:
client/src/lib/reel-utils.ts

Current old format:
{ItemAbbr}-{Size}-{BrandAbbr}-R{seq}

Replace for newly created reels with:
R-{SC|MC}-{SIZE}-{CONFIG}-{SEQ}

Generation rules:

1. Core code:
- MC if item name/config contains:
  - 4C+G
  - 3C+G
  - 2C+G
  - 4C
  - 3C
  - 2C
- Otherwise SC for reel-eligible wire/cable items.

2. Size code:
Use item.sizeLabel first.

Normalize:
- #8 → 008
- 8 → 008
- #12 → 012
- 12 → 012
- #1 → 001
- 1/0 → 10
- 2/0 → 20
- 3/0 → 30
- 4/0 → 40
- 250 → 250
- 350 → 350
- 500 → 500

Remove #, spaces, quotes, and unsafe characters.

3. Config code:
For Multi Core:
- 4C+G → 4CG
- 3C+G → 3CG
- 2C+G → 2CG
- 4C → 4C
- 3C → 3C
- 2C → 2C

For Single Core:
Detect color/config from item.name:
- Green, GRN, Ground → GRN
- Black, BLK → BLK
- White, WHT → WHT
- Red → RED
- Blue, BLU → BLU
- Brown → BRN
- Orange → ORG
- Yellow → YEL
- Gray, Grey → GRY

If no config/color is detected:
- Use UNK for new reel creation only if the UI currently requires a Reel ID.
- But show a warning/helper text if possible:
  "Color/config could not be detected. Please verify Reel ID."

4. Sequence:
Use 3 digits:
001, 002, 003

Final examples:
#8(4C+G) THHN/THWN-2 600V → R-MC-008-4CG-001
#12 Ground Wire THHN/THWN-2 → R-SC-012-GRN-001
500 kcmil Black THHN → R-SC-500-BLK-001

Do not include brand in the new Reel ID.
Brand remains stored in wire_reels.brand.

Part 2 — Update getNextReelSeq compatibility

In server/storage.ts, update getNextReelSeq(itemId).

Current logic likely parses old IDs ending in:
R001

It must support both:
Old:
MCCT6-#8-XX-R001

New:
R-MC-008-4CG-001

Requirement:
- Extract the last 3-digit sequence at the end of reel_id.
- Support both R001 and -001 endings.
- Continue including soft-deleted reels when calculating max sequence, so sequence numbers are not reused.

Recommended logic:
const match = reel.reelId.match(/(?:R|-)?(\d{3})$/i);

If no match, skip that reel.
Return max + 1.

Be careful:
Do not change reel length logic.
Do not change quantity sync.
Do not change movement logic.

Part 3 — Existing Reel ID Rename Preview

Add an admin-only preview feature.

Preferred location:
- If there is an Admin Cleanup / SKU Cleanup area, add a new tab:
  Reel ID Cleanup
- Otherwise add a small admin-only section/page reachable from Admin tools.

Create backend preview endpoint:

GET /api/admin/reel-id-preview

This endpoint should return existing reels with:
- reelDbId
- itemId
- itemName
- sizeLabel
- currentReelId
- proposedReelId
- coreCode
- sizeCode
- configCode
- sequence
- status
- reason

Preview status values:
- ready
- already_new_format
- ambiguous
- conflict
- invalid_sequence
- missing_item
- skipped

Rules:

1. Already new format:
If currentReelId already matches:
R-SC-...
or
R-MC-...
Then status = already_new_format.
Do not offer Apply.

2. Sequence:
For existing reels, preserve the old sequence if possible.

Examples:
MCCT6-#8-XX-R001 → sequence 001
THHN-1/0-SW-R003 → sequence 003

If sequence cannot be parsed:
status = invalid_sequence
Do not offer Apply.

3. Config:
If proposed config is UNK:
status = ambiguous
Do not offer Apply.

Reason:
Do not convert unclear old IDs into unclear new IDs like:
R-SC-008-UNK-001

4. Conflict:
If proposedReelId already exists on another reel:
status = conflict
Do not offer Apply.

Check uniqueness according to the current DB constraint.
If reel_id is globally unique, check globally.
If reel_id is only unique per item, check per item.
Inspect shared/schema.ts before deciding.

5. Missing item:
If reel has no valid joined item:
status = missing_item
Do not offer Apply.

6. Ready:
Only when:
- old sequence parsed
- coreCode found
- sizeCode found
- configCode found and not UNK
- proposedReelId does not conflict
Then:
status = ready

Important:
