Fix TOOLS & ASSETS asset display, preserve accidental category moves, add Undo, and add quantity-based Asset ID generation.

Context:
- TOOLS & ASSETS category already exists.
- trackingMode = "asset" already exists.
- tool_assets table/API may already exist.
- Current issue: after moving existing items into TOOLS & ASSETS, existing quantity rows are hidden and only the asset placeholder is shown.
- Users need existing quantity visible because asset IDs should be generated from current quantity.
- Users may accidentally move items into TOOLS & ASSETS, so moving categories must be reversible and non-destructive.

Main rule:
Category move is NOT asset conversion.
Asset conversion is NOT asset ID generation.
These must be separate explicit actions.

Do not:
- Do not delete existing items.
- Do not change existing quantityOnHand values.
- Do not auto-convert items to asset tracking just because they are moved into TOOLS & ASSETS.
- Do not auto-generate asset IDs during category move.
- Do not change normal material quantity logic.
- Do not change reel logic.
- Do not change wire reel movement logic.
- Do not change Field Mode.
- Do not change Excel export.
- Do not change Equipment page.
- Do not hard-delete tool assets.

------------------------------------------------------------
PART 1 — Fix TOOLS & ASSETS display logic
------------------------------------------------------------

Current bug:
FamilyGroupCard currently treats the whole TOOLS & ASSETS category as asset mode.

Bad logic example:
const isAssetCategory = data.category.name === "TOOLS & ASSETS";
const isAssetGroup = isAssetCategory || group.items.some(i => i.trackingMode === "asset");

This hides existing size/quantity rows.

Required fix:
Do not treat every item in TOOLS & ASSETS as asset-tracked only because the category name is TOOLS & ASSETS.

Use item trackingMode.

Rules:
1. If trackingMode === "asset":
   - show asset management UI
   - show legacy quantity reference
   - show existing inventory rows
   - show asset roster if assets exist

2. If trackingMode === "standard" or null:
   - show normal quantity/size rows
   - do not show asset roster
   - do not show Generate Asset IDs button

3. If trackingMode === "reel":
   - keep existing reel behavior unchanged

4. TOOLS & ASSETS may contain both:
   - asset-tracked items
   - standard quantity items

Example:
TOOLS & ASSETS
  Ladders
    A Type Ladder 10FT
      trackingMode = asset
      Qty 10 EA
      Asset IDs LAD-A10-001 ~ LAD-A10-010

  Safety / PPE
    Gloves
      trackingMode = standard
      Qty 200 EA
      No asset roster

PART 3 — Generate Asset IDs from current quantity
------------------------------------------------------------

Add an Admin Inventory button for asset-tracked items:

Generate Asset IDs

This should generate missing asset rows based on current quantityOnHand.

Example:
A Type Ladder 10FT
SKU = LAD-A10
quantityOnHand = 10

Generate:
LAD-A10-001
LAD-A10-002
LAD-A10-003
...
LAD-A10-010

Default values:
- status = available
- condition = good
- locationId = item's primary/current location if safely available, otherwise null
- projectId = null
- assignedTo = null

Display labels:
available → In Stock
in_use → In Use
repair_needed → Repair Needed
under_repair → Under Repair
out_of_service → Out of Service
lost → Lost
retired → Retired

------------------------------------------------------------
PART 4 — Asset ID prefix and numbering
------------------------------------------------------------

Use the item SKU as the default Asset ID prefix.

Example:
SKU = LAD-A10
Asset IDs:
LAD-A10-001
LAD-A10-002

Normalize prefix:
- uppercase
- trim spaces
- replace unsafe characters with hyphen
- collapse repeated hyphens

If SKU is missing, do not generate assets.
SKU should already be required.

Numbering rules:
- Check existing active and inactive tool_assets.
- Find the highest existing sequence for that prefix.
- Generate from max + 1.
- Do not reuse deleted, retired, or deactivated numbers.

Example:
Existing:
LAD-A10-001
LAD-A10-002
LAD-A10-003 inactive

Next generated asset must be:
LAD-A10-004

Do not reuse:
LAD-A10-003

------------------------------------------------------------
PART 5 — Generation count
------------------------------------------------------------

Calculate:

targetCount = item.quantityOnHand
currentActiveAssetCount = active assets for this item
missingCount = targetCount - currentActiveAssetCount

If missingCount <= 0:
Show:
All assets are already generated.

If missingCount > 0:
Generate exactly missingCount new assets.

Example:
quantityOnHand = 10
active assets = 7

Generate 3 assets:
LAD-A10-008
LAD-A10-009
LAD-A10-010

Do not change quantityOnHand.

------------------------------------------------------------
PART 6 — Backend endpoint
------------------------------------------------------------

Add this endpoint if it does not already exist:

POST /api/items/:itemId/assets/generate-from-quantity

Server must:
- validate item exists
- validate item.trackingMode === "asset"
- validate quantityOnHand is a positive integer
- use item.sku as the prefix
- normalize prefix safely
- calculate missingCount
- check existing active + inactive assets
- avoid duplicate sequence numbers
- insert generated assets
- return created assets and summary

Do not trust client-generated asset IDs.
Asset ID generation must happen server-side.

PART 9 — Undo toast after category move
------------------------------------------------------------

After successful move, show toast:

Moved to {newCategoryName}. [Undo]

Undo should restore:
- previous categoryId
- previous category name
- previous trackingMode if the move operation changed it
- previous subcategory/family position if safely available

Since normal move should not change trackingMode, restoring previous categoryId is usually enough.

Client should store previous values before move:
- item/group id
- previousCategoryId
- previousCategoryName
- previousTrackingMode
- previousSubcategory if applicable

When Undo is clicked:
- call the existing move/update endpoint to restore previous category
- refresh inventory data
- show success toast:
Move undone.

If Undo fails:
- show visible error toast
- do not silently fail

- category move
