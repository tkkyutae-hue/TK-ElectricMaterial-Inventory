# 공통 화면·로그인 사용성 준비본

## 반영 상태와 경계

**실행 코드에 반영하지 않은 준비본이다.** `prepared/` 안의 `.txt` 파일은 원본 경로에 대응하는 완전한 후보 소스이며 자동 적용하지 않는다. 기존 실행 앱의 자동 갱신, 서버 시작/재시작, 실제 로그인·DB·세션·저장소 접근, 설정 변경, 배포는 수행하지 않는다.

후속 작업은 이 준비본을 함께 읽되 현재 실행 코드에 이미 반영되었다고 가정하지 않는다. 검증기는 일회용 `/tmp` 작업본에만 후보 소스를 조합한다. 기존 Indiana 준비본은 덮어쓰지 않는다.

## 원본에서 확인한 불편과 변경

| 확인한 불편 | 후보 변경 |
|---|---|
| Field/Admin 헤더에 현재 지점의 명시적 글자 표시 없음 | 변경 불가능한 문서 지점을 읽어 `지점: Indiana/Savannah`와 Field/Admin 모드를 별도로 표시 |
| 지점 선택 화면으로 나가는 링크에 버튼이 중첩됨 | 기존 선택 URL을 유지하는 단일 링크로 정리하고 작성 중 작업·미확정 저장 확인 안내 추가 |
| 기존 모바일 헤더의 고정 높이가 지점 표시와 안내를 수용하지 못함 | 이 두 업무 헤더에만 적용되는 줄바꿈/자동 높이 스타일 추가 |
| 로그인 상단의 큰 중복 로고, 작은 라벨, 누락된 입력 라벨 연결 | 실제 TK 헤더 브랜드는 유지하고 중복 큰 로고 영역을 줄임. 읽기 쉬운 라벨과 입력 id 연결 |
| 비밀번호 표시 버튼이 탭 이동에서 제외되고 접근 가능한 이름 없음 | 키보드로 조작 가능한 44px 버튼, 현 언어의 표시/숨기기 이름과 pressed 상태 |
| 밝은 테마 오류 글자 대비 부족, Google 설정 오류 영문 고정 | 테마별 오류 색상, 줄바꿈/알림 역할/입력 오류 연결, 3개 언어 설정 안내 |
| 로그인 처리 중 버튼 외 경로의 반복 제출 방어 부족 | 기존 요청 프로토콜을 유지한 동기 잠금으로 처리 중 재제출 차단 |
| 공통 빈 화면/오류 기본 문구 영문 고정 및 낮은 대비 | 기존 API/커스터마이징을 유지하면서 현 언어 기본 문구와 테마 토큰 사용 |

인증 방식·POST 대상·Google 로그인 URL·가입 경로·권한·수량 계산은 바꾸지 않는다. 지점 선택은 기존 `BranchSelectorLink`의 새 문서 이동을 그대로 사용한다. 안내는 초안의 지점 간 보존을 보장하지 않으며, 미확정 저장 결과를 먼저 확인하도록 한다.

## 후속 화면에서 재사용할 인터페이스

- `BranchModeMarker`: `mode="field" | "admin"` 및 선택적 className/color/mutedColor. 문서 지점이 확인되지 않으면 임의로 Savannah라고 표시하지 않는다.
- `BranchExitGuidance`: 선택적 className/color. 표시 전용이며 저장·이동·초안 삭제를 수행하지 않는다.
- `LoadState`: 상태를 부모가 명시한다. 데이터 요청이나 캐시·전역 상태는 소유하지 않는다.
  - `empty`: 자료 없음. 검색 결과 없음과 구분.
  - `filtered`: 검색·필터 결과 없음. 선택적 `onClearFilters`.
  - `loading`: 보이는 로딩 문구와 접근 가능한 busy/status 표시.
  - `error`: 연결/불러오기 실패. 선택적 `onRetry`.
  - `forbidden`: 권한 제한. 선택적 `onContactAdmin`.
  - `unconfigured`: 기능 미설정. 선택적 `onContactAdmin`.
- 모든 상태는 선택적 title/description/className을 받는다. 다른 상태의 행동을 잘못 넘기지 않도록 타입이 구분되어 있다.
- `EmptyState`와 `ErrorState`의 기존 props와 사용자 지정 문구/행동은 유지한다.
- 공통 표시 문구는 기존 `LanguageProvider`의 언어를 사용하는 `common-messages`/`use-common-messages` 영역에 한정한다. 기존 지점 전환·미디어 번역의 같은 구조를 재사용하며 별도의 언어 저장소를 만들지 않는다.
- Field/Admin 후속 작업은 위 공통 컴포넌트를 화면의 실제 요청 상태에 연결한다. 모든 업무 페이지에 이미 적용되었다는 의미가 아니다.

## 변경 파일 확인

`manifest.json`에 각 후보 파일의 SHA-256과 대응 실행 소스의 기준 SHA-256(신규 파일은 null)이 있다. 반영 전 기준이 달라졌다면 덮어쓰지 말고 차이를 검토해야 한다.

## 격리 검증

다음 명령은 기존 설치 패키지만 사용하며 애플리케이션 서버를 띄우지 않는다.

```sh
env -i PATH="$PATH" LANG=C.UTF-8 NODE_ENV=test \
  node development/inventory-usability-common/verify.mjs
```

검증기는 자격증명 없는 환경을 확인하고 `/tmp`에 before/after 소스 작업본을 만든다. 후보 타입 검사는 네트워크·DB·자식 프로세스를 차단하는 기존 오프라인 가드 아래 실행한다. 브라우저는 이미 설치된 Chromium을 사용하며, 합성 `.invalid` 문서를 로컬 응답으로만 제공한다. 포트나 HTTP 서버를 만들지 않는다.

실제 수정 컴포넌트와 언어/테마 공급자를 렌더링하되, 인증 훅과 로그인 HTTP 경계만 합성 응답으로 대체한다. 이는 실제 계정의 인증 성공이나 로그인된 업무 흐름을 검증한 것이 아니다.

결과는 `results.json`에 기록한다. 같은 자료·고정 시각·언어·테마·화면 크기의 전후 이미지와 자체 포함 HTML 비교본은 Git/배포에서 제외된 `generated-artifacts/inventory-usability-common/`에 생성한다. 비교본은 별도 검토용 파일로 제공한다.

프로젝트의 기존 전체 서버/DB/권한 검사 묶음은 다시 실행하지 않는다. 타입 검사 외에는 이번 변경에 관련된 검사만 수행한다. 실제 앱/Preview를 캡처하거나 테스트하지 않는다.

### 이번 실행 결과

- 후보 전체 타입 검사 통과.
- 렌더링/입력/헤더 행렬 54개 경우: 로그인·Field 헤더·Admin 헤더 × 320/390/1280px × 한국어/영어/스페인어 × 두 테마.
- 공통 상태 표시/허용 동작 36개 경우: 여섯 상태 × 세 언어 × 두 테마.
- 실제 준비본 로그인 핸들러의 처리 중 중복 제출 차단·실패 후 입력 유지·언어/테마 변경·재시도 성공 묶음 1개 경우.
- Google 미설정 안내의 긴 문구·겹침 검사 세 언어 3개 경우.
- Field 하위 화면 뒤로 링크·기존 새 문서 지점 선택 URL 검사 1개 경우.
- 합계 **95개 합성 검사 경우 통과**, 브라우저 예외 및 예상 밖 요청 0개. 위 묶음은 각각 한 번만 계산했다.
- 동일 조건 전후 화면 **7쌍(14장)**을 HTML 비교본으로 제공한다.
- 검증 중 후보를 복사한 뒤 실행 소스가 바뀌지 않았음을 해시로 확인했다.

준비/검증 도구를 만드는 과정의 작업본 설정 및 번들 구성 오류는 최종 실행에서 해결했다. 과거 실행을 최신 준비본의 증거로 사용하지 않으며, 위 결과는 최종 `manifest.json`의 후보 해시에 해당한다.

## 남겨 둔 항목

- 첨부에서 명시한 기존 시작 설정 테스트 실패 및 실제 로그인 후 업무 흐름 미검증은 이번 작업으로 해결되었다고 판단하지 않는다.
- 화면 이동 대기시간을 측정하거나 해결한 작업이 아니다.
- 사진·첨부의 실제 대상·저장소 설정·접근 승인·기존 사진 도입은 이 작업에서 확인하거나 실행하지 않았다. 해당 후속 작업에서 현재 연결과 필요한 설정/승인을 구체화한다.
- 실행 소스로의 반영·서버 재시작·운영 배포와 실제 연결 검증은 별도 승인 범위다.
