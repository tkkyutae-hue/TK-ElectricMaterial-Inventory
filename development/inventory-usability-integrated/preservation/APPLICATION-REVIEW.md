# 실제 적용 변경목록 — 검토용, 적용 승인 아님

## 공통 구조와 범위

저장소 하나, 공통 코드베이스·서버·배포 하나를 유지한다.
Savannah/Indiana는 기존 Field/Admin을 공유하며 업무 DB·파일 소유권·
접근권한을 분리한다. `Indiana`는 검토/보존 브랜치이며 운영 지점 분리
수단이 아니다. 최종 `main` 통합은 별도 승인 사항이다.

실제 적용 후보는 상위 `manifest.json`의 35개 경로다. 기존 실행 기준
해시와 다른 경우 그대로 덮어쓰지 않는다. 원본 후보를 재개발하지 않는다.

| 묶음 | 검토할 실제 적용 내용 |
| --- | --- |
| 공통 | Field/Admin/로그인의 기존 디자인 기반 헤더·지점/모드 표시·읽기 상태·언어/테마 메시지 |
| 미디어 | 기존 갤러리/첨부/라이트박스와 권한 있는 지점 미디어 경로 연결. 파일 소유권이나 provider를 바꾸지 않음 |
| Field | 기존 카트·요청 편집/취소·피드백과 초안 보호 경로 |
| Admin | 기존 요청 상태 처리·완료/허용된 Undo·필터·오류 표시 |
| 작업 ID | 같은 문서 안에서 원래 작업 ID·본문·revision·완료 원본을 유지하고 결과 확인 후 재시도. 현재 권한을 우회하지 않음 |
| 통합 보완 | Inventory URL을 목록 상태 원본으로 사용. FieldTransactions 탭과 URL·뒤로/앞으로 연결 |

이 목록에는 실제 시작 구성/DB 스키마 적용/기존 자료 변환이 포함되지 않는다.
그런 변경이 필요한 것으로 확인되면 별도 영향과 승인을 먼저 제출한다.

## 남은 승인과 중단 조건

1. **보존 전 조건:** 현재 설치 GitHub Apps와 업로드 자동화 영향 확인.
   기존 CLI 쓰기 권한과 Webhook/Actions 0개를 확인했고, 사용자가 현재도
   Replit Signin만 설치돼 있다고 확인해 보존 조건이 충족됐다.
2. **보존 완료 조건:** `Indiana`의 새 커밋 식별자와 원격 변경 파일의 해시 일치.
   이 업로드 전 고정 문서와 별도로 최종 커밋/해시 대조 완료 기록을 제출한다.
3. **실제 반영 승인:** 적용 파일·지점·역할·허용 작업·실행 시점과
   재시작 범위. 이번 GitHub 보존 승인을 여기에 확장하지 않는다.
4. **업무 안전:** 기존 직원 탭, 작성 중 초안, 미확정 요청의 처리 방안.
   새로고침/로그아웃/새 ID로 임의 재제출해 미확정 상태를 없애지 않는다.
   Field 카트의 기존 layout 수명과 문서/계정/지점 변경 경계를 유지한다.
5. **실환경 검증 승인:** 실제 계정/업무/저장소 접근은 별도 승인 범위를
   명시해야 한다. 현재 합성 결과로 실제 업무 성공을 주장하지 않는다.
6. **준비 상태:** 기존 시작 설정 테스트 실패, 실제 저장소/과거 사진 연결,
   실제 로그인 업무·휴대폰 경로와 화면 이동 지연은 미해결/미검증이다.
   필요한 확인 범위가 승인되지 않았으면 중단한다.
7. **배포 승인:** `main` merge와 Publish/Republish는 별도 판단.
   이번 범위에서는 둘 다 실행하지 않는다.
