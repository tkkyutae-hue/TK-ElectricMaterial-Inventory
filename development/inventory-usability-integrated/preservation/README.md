# Indiana 원격 보존 — 업로드 전 고정 기록

## 업로드 직전 확인 상태

- 대상 저장소: `tkkyutae-hue/TK-ElectricMaterial-Inventory` 하나.
- 정확한 대상: [`Indiana`](https://github.com/tkkyutae-hue/TK-ElectricMaterial-Inventory/tree/Indiana).
- 원격에서 확인한 기준 커밋:
  `40da01ee24d9154166462bc96e295de191f9ae75`.
- 과거 `indiana-phase2` 지정은 이번 승인 대상이 아니다.
- 기존 GitHub CLI가 이 Replit에서 실제 저장소 조회에 성공했고
  `permissions.push: true`를 반환했다. ChatGPT 인증을 재사용하거나
  그 성공을 근거로 삼지 않았다. 새 인증정보·권한 확대는 없다.
- 현재 저장소 Webhook 0개, Actions 워크플로 0개를 확인했다.
- 사용자가 현재 저장소 접근 가능 설치 앱을 확인해 **Replit Signin만
  있다**고 답했다. 기존 쓰기 권한과 Webhook/Actions 확인을 합쳐
  `Indiana` 검토용 보존 조건이 충족됐다.
- 이 문서는 업로드 전에 고정한 자료다. 자체 보존 커밋 해시를 본문에
  넣는 순환 참조를 피하며, 최종 커밋·원격 동일성 결과는 업로드 후
  별도 완료 기록과 사용자 보고로 제출한다.

사용자 승인은 이 브랜치의 검토용 보존에 한정된다. 최종적으로 별도
승인된 변경만 공통 `main`에 합칠 목적이다. 브랜치는 지점 운영 경계가
아니다. Savannah/Indiana는 기존 Field/Admin·디자인·기능, 공통 코드·서버·
배포를 공유하고 업무 DB·파일 소유권·지점 접근권한을 분리한다.
별도 제품·저장소·영구 지점 운영 브랜치를 만들지 않는다.

## 완료된 검사 재사용

`audit-inputs.mjs`는 실제 앱/DB/업무 API를 호출하거나 기존 검사를
실행하지 않는 파일·해시 감사 도구다.

```sh
env -i PATH="$PATH" LANG=C.UTF-8 NODE_ENV=test \
  node development/inventory-usability-integrated/preservation/audit-inputs.mjs
```

다음을 확인한다:

- 후보 35개 SHA-256, 대응 실행 기준 파일 해시와 신설 파일의 부재.
- 명령 검사와 실제 라우터 검사의 최종 후보 집합 일치.
- 조합의 선행 manifest·후보 및 명령 검사 upstream 입력 해시.
- 기존 결과의 App/Wouter 53개·작업 처리 46개·receipt 쿼리 계약 6개 및
  TypeScript 통과 기록. **이는 과거 실행 결과의 재사용이며 신규 통과 수가 아니다.**
- 재현 입력 전체는 결과 기록을 포함하는 로컬 Git 커밋과 파일 단위 비교.
  후보의 실행 당시 해시는 원래 manifest를 기준으로 확인한다.
  전체 재현 트리 해시는 이번에 추가 기록한 것이며, 실행 당시 별도
  전역 해시를 기록했던 것처럼 표현하지 않는다.

`hash-audit.json`이 현재 대조 결과, `baseline-index.json`이 재현 입력
위치/해시, `remote-source-index.json`이 특정 원격 기준의 파일 메타데이터다.
로컬 결과 기록 커밋은 원격 보존 커밋이 아니므로 혼동하지 않는다.
로컬 `main`의 미업로드 커밋 전체를 전송하지 않는다.

## 재현 기준 소스

필요한 정적 기준 소스만 경로별로 구분했다:

1. 원격 기준 커밋의 Git blob과 같은 파일은 고정된 커밋/경로/해시로 참조.
2. 다른 소스는 `baseline/<원래 경로>.txt`의 실행되지 않는 스냅샷.
3. 그 위에 `../prepared/<원래 경로>.txt` 35개를 적용하는 구조.
4. 공통/미디어/Field/Admin/작업 ID 준비본의 manifest·후보는 기존 검사
   도구의 해시 확인 입력이므로 함께 보존 목록에 포함한다.

재현은 나중에 허용된 별도 오프라인 작업 디렉터리에만 복원한다.
원격 고정 파일은 원본 경로에, 스냅샷은 `.txt`를 제거한 원본 경로에
두고 후보를 마지막에 덮는다. 기존 검사 도구는 이 구조의
`development/inventory-usability-integrated` 아래에 둔다.
각 단계의 SHA-256을 대조한 뒤에만 기존 검사를 사용할 수 있다.
현재 실행 작업공간에 복원/적용하거나 패키지를 설치하지 않았다.

브라우저 검사에서 쓰는 첨부 로고 별칭은 Git에 추적되지 않았지만,
기존 `server/assets/tk_logo.png`와 바이트가 같고 그 공개 브랜드 로고의
Git blob은 원격 기준과 로컬 결과 커밋 양쪽에서 확인됐다.
`baseline-index.json`은 이를 별칭→고정 원본으로 명시한다.
실제 직원/업무 사진이나 새 이미지 생성물을 수집하지 않는다.

원래 두 검사는 `client/src`, `shared`, `server`, `tests/helpers`의
정적 소스와 패키지/타입/Vite/Tailwind 기준 설정을 복사했다.
재현용 목록은 그 정적 텍스트와 기존 공개 로고 참조만 포함한다.
업무용 엑셀 템플릿·사진·첨부 자료는 검사에 필요하지 않아 제외했다.
리터럴 자격증명 패턴의 발견/수동 분류는 `source-review-findings.json`에
값을 노출하지 않고 남겼다. 이 좁은 검토를 전체 보안 검사라고 부르지 않는다.

## 업로드와 병합 후 스크립트의 구분

원격의 `.replit`은 `scripts/post-merge.sh`를 postMerge로 지정한다.
해당 스크립트가 **실행된다면** 패키지 설치와 DB 열 추가 명령을 수행한다.
이 사실은 보존 브랜치에 파일을 업로드하는 것만으로 그 명령이
실행된다는 증거가 아니다. 스크립트를 실행하거나 설정을 바꾸지 않았다.

Replit의 후속 작업 병합에는 설정 스크립트와 워크플로 조정 경로가
있으므로 실제 merge/완료 처리도 이번 범위와 구분해야 한다.
공식 Publishing 문서상 Git push와 Publish/Republish도 별개다.
그러나 이것만으로 타사 GitHub App의 push 이벤트 자동화를 배제하지 않는다.

기존 CLI 인증으로 `GET /user/installations`를 시도했지만 HTTP 403:
그 API는 GitHub App에서 발급한 사용자 토큰 유형을 요구한다.
이는 저장소 쓰기 권한 부족/인증 만료의 증거도, 설치 앱 0개의 증거도 아니다.
다른 유형 토큰 발급·권한 확대·보안/공개 설정 변경으로 우회하지 않는다.

사용자의 2026-10-23 관찰(Webhook 없음, Replit Signin 하나)은 역사적
보조 근거로 보존했다. 현재 전체 자동화 안전성으로 확대 해석하지 않는다.

이후 사용자가 현재 설치 앱 목록도 Replit Signin뿐임을 직접 확인했다.
이는 설치 앱에 관한 현재 확인이며, Replit 쓰기 인증은 기존 CLI의 실제
조회/권한 응답으로 별도 확인했다. 새 권한 발급·설정 변경은 없다.
확인된 경로에서 `Indiana` 보존만 진행하며 다른 자동화가 없다는
무제한 보증이나 실제 앱 활성화 승인으로 확대하지 않는다.

## 실제 원격 쓰기의 한계

- 그 시점의 `Indiana` tip을 다시 비교한다. 이동했다면 해당 변경만 검토한다.
- 확인된 원격 tip을 부모로 하고 검토한 파일 목록만 추가한다.
- 로컬 `main`에서 Sync/Push하거나, 브랜치 전환·pull·merge·reset하지 않는다.
- 기존 원격 실행 소스·설정·워크플로·루트 패키지 파일을 바꾸지 않는다.
  보존 소스는 모두 기존 `development/` 아래 검토용 자료다.
- 강제 업로드·`main` 변경·merge·실제 DB/사진/업무 API·실행 앱 적용·
  시작/재시작·환경/포트/패키지/워크플로 변경·배포를 하지 않는다.
- 결과 커밋 식별자와 변경 파일의 원격 SHA-256을 대조해야 보존 완료다.
  그 결과는 이 업로드 전 고정 기록과 구분해 제출한다.
