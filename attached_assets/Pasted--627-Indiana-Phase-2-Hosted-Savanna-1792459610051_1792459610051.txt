[C. Hosted Indiana 설계안 — 문서만 작성, 실행 금지]
docs/indiana-hosted-plan.md 를 indiana-phase2 브랜치에 작성한다.
- Indiana Replit 프로젝트 생성 방식: Savannah Repl 복제(Remix) 금지. GitHub에서 가져올 경우 .replit의 Savannah 설정(objectStorage.defaultBucketID, GOOGLE_CALLBACK_URL, ADMIN_SEED_TOKEN, deployment, postMerge)을 Indiana에서 어떻게 분리할지 제시한다.
- 필요한 신규 자원(DB, 세션 secret, Google OAuth client 또는 콜백, 오브젝트 스토리지 버킷)과 각각의 승인 필요 여부, 비용 발생 여부.
- 런타임 검증기 hosted 모드:
  · server/db.ts의 서브넷 스캔 fallback을 Indiana에서 비활성화하고, 명시적으로 지정한 Indiana DB 외에는 연결을 거부한다.
  · 별도 프로젝트·DB 자원의 비밀값이 아닌 식별정보와 연결 근거로 승인된 Indiana DB인지 확인한다.
  · Savannah DB 식별정보는 차단 목록으로 두고 일치 시 시작을 거부한다. 불명확하면 시작을 차단한다.
  · 지점 DB 검증을 통과하기 전에는 seed·migration·backfill·sync·표식 기록을 포함한 어떤 DB 쓰기도 실행하지 않는다.
- 공통 코드베이스 운영 방식: 저장소 하나, 지점 차이는 BRANCH_CODE 등 환경변수로만, Savannah 기본 동작 변경 없음. branch-foundation 분리 소스를 공통 구조로 합치는 방법과 Savannah 영향.
- 다음 항목의 현재 상태와 처리안: Savannah 전용 seed(C.E.S 이름 변경·공급사 연결), scripts/post-merge.sh, Jibble 10분 주기 동기화, Monday 연동, drizzle-kit push 방식, 재고 외 모듈(일일보고·근태·Crew Dispatch·완료보고서·장비·TV 대시보드)의 Indiana 사용 여부.
- 결정 필요 사항: 입고·출고·반품은 창고별 잔고를 갱신하지 않고 이동·조정만 갱신하여, 신규 Indiana에서 입고 후 창고 간 이동이 실패하는 문제. 코드는 수정하지 않는다. Savannah 기존 기록은 재계산하지 않는다는 전제에서, 앞으로 발생할 거래에 적용할 규칙의 선택지와 각 선택지의 Savannah 영향만 정리한다.

[D. 실행 금지]
Indiana Repl 생성, 유료 자원 생성, Google·스토리지 설정, 실제 카탈로그 적재, 운영 배포, Savannah 작업공간 병합은 하지 않는다. 승인이 필요한 지점에서 멈추고 보고한다.
